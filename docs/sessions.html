Building Blocks

Agent Sessions

Every agent run happens inside a hidden pseudo-terminal — node-pty on POSIX, ConPTY on Windows — so no console window flashes. Browser viewers attach to a live session over WebSocket, and the agent keeps running even if every viewer closes.

A provider plugin declares clawdevbox.agent_clis[] in its manifest and exports a module with a spawnSession() entry point. See Extensibility → CLI providers.

How sessions run

  1. Spawn

    The recipe runner (or a trigger's spawn dispatch) calls the provider's spawnSession(ctx, opts), which launches the CLI inside a hidden pty with the MCP config wired in.

  2. Attach

    A browser viewer subscribes over WebSocket and streams the raw xterm. Multiple viewers can watch the same session; each gets its own attach.

  3. Persist

    The agent process outlives its viewers. tmux-backed sessions survive across reconnects and are reconciled on server startup.

tmux-backed sessions

On platforms with tmux, sessions run inside persistent cdb_<id> tmux sessions so they can be resumed and multi-attached:

ConceptMeaning
sessionA persistent cdb_<id> tmux session holding one agent CLI.
spawnprovider.spawnSession(ctx, opts) launches the agent into that session.
resumeThe same session id can be re-attached / resumed after a disconnect.
terminals panelThe browser UI listing live sessions for attachment, keyed by recipe instance.

The terminals sidebar is keyed by recipe instance; an agent_sessions mapping resolves a CLI session to its instance. Inline recipes run in the parent agent's session, so they resolve their terminal through the parent.

Session tools

Drive a running agent session directly:

ToolPurpose
session.listList active agent sessions.
session.readRead a session's recent output / transcript.
session.sendSend input (a message / keystrokes) to a session.
session.killTerminate a session.

Long-running daemons

For processes that must stay alive independently of any one agent run — dev servers, watchers, emulators — use the daemon.* tools. They register, supervise, and tail long-running processes:

ToolPurpose
daemon.registerRegister a long-running process definition.
daemon.start / daemon.stop / daemon.restartControl the process lifecycle.
daemon.list / daemon.getList registered daemons / read one's status.
daemon.read_logsTail a daemon's captured stdout/stderr.
daemon.deleteRemove a daemon definition.
