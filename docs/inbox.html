Building Blocks

Inbox & Workflow

The inbox is the human's side of the loop — a persistent notification center where agents surface work, post progress, and ask for a decision. It's built from four kernel entities: inbox items, threads, messages, and approvals.

The data model

Inbox item
A persistent card representing one actionable thing (a PR, work item, incident, epic, or manual ask). Carries kind, state, priority, and an agent-authored prose body.
Thread
An append-only run attached to an inbox item. Recursive via parent_thread_id for epic decomposition.
Message
An event record on a thread — agent text, a tool call, a result, a view emission, or a user message.
Approval
A question/decision round-trip bound to a thread. Suspends the thread until the user answers.

The core workflow

  1. Surface

    The agent creates or updates a card with inbox.upsert (idempotent on id), setting a kind, an agent message, and a tone.

  2. Ask (if needed)

    Needs input? Attach a question to the item, or open an approval on its thread. The user answers in the inbox UI or an approval modal.

  3. Progress

    The agent posts updates as thread messages and transitions state (inbox.set_state) — new → open → snoozed → archived → done.

  4. Resolve

    On completion the item is marked done or archived. inbox.mark_read and inbox.snooze manage attention.

Hard rule: inbox tools require a session id

The inbox.* tools only work inside a ClawDevbox-spawned session (where CLAWDEVBOX_SESSION_ID / the session header is set). Without a session id you're not in a ClawDevbox session — respond in normal chat instead. Never use approval.request as a substitute for asking a question.

Asking the user a question

When an agent needs input, it calls inbox.upsert with questions: [...]. The question is persisted on the item, and the thread/session stays the anchor for the round-trip — so the answer flows back to the right run.

The approval round-trip

  1. Request

    approval.request opens a pending approval and moves the thread to awaiting_user. It carries a question, options, and a renderer-minted nonce.

  2. Decide

    The UI renders a decision modal. The user picks an option (or free-text, if allowed).

  3. Resolve

    approval.resolve stores the answer, appends an approval_resolved message, and returns the thread to running.

Notifications: inbox vs ui vs notify

CallEffect
inbox.upsertPersistent inbox row + list refresh + optional push. Use for durable, actionable items.
ui.notifyA one-off signal — emit an SSE topic change and/or a browser push in one call.
notify.sendPush only — a browser push notification to all subscribed devices.

Inbox, thread & approval tools

ToolPurpose
inbox.upsertCreate/update an item — body, attachments, labels, questions, optional push.
inbox.list / inbox.readList items with filters / read one item + recent messages.
inbox.replyAppend a reply to an item's reply chain.
inbox.set_state / inbox.snooze / inbox.archive / inbox.mark_readManage item state and attention.
thread.spawnCreate a thread for an inbox item (does not spawn the CLI itself).
thread.append_message / thread.readAppend / read the thread timeline.
thread.set_state / thread.cancel / thread.wakeSet state, cancel (recursively), or mark a thread running again.
approval.request / approval.resolve / approval.list_pendingOpen, resolve, and list pending approvals.
notify.send / ui.notifyPush / SSE-topic notification facade.
