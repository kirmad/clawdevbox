Artifacts & Renderers

An artifact is a folder an agent publishes so a human can look at it in the browser — a design doc, a PR review, a code walkthrough. A renderer turns that folder into an interactive view, chosen by the artifact's declared type.

The artifact model

Every artifact is a folder at <workspace>/artifacts/<id>/ with a required manifest.json plus free-form content files. The manifest's type is the dispatcher key.

<workspace>/artifacts/design-2401/
├── manifest.json      { "type": "markdown", "title": "Auth design" }
└── content.md         # the content the renderer displays

Built-in renderers

Three renderers ship out of the box:

RendererExpected filesWhat it shows
markdowncontent.mdA markdown article with fenced-code highlighting and Mermaid diagram rendering.
pr-reviewreview.json (+ optional walkthrough.json, pr.json, file snapshots)A full PR review UI: hierarchical file tree, full-file diffs, and a comment rail.
walkthroughwalkthrough.json (+ optional file snapshots)A full-viewport code walkthrough with a floating step overlay on top of the code.

Publishing an artifact

An agent skill writes the content files, then calls artifact.add to register the folder and make it discoverable. The call returns up to three URLs:

URLUse
view_urlLoopback browser page — always present when the server is up.
tunnel_view_urlYour devtunnel URL — open from your other devices on the same tunnel account.
share_urlTenant-scoped share-tunnel URL — safe to hand to a colleague (no /mcp bearer needed).

Call artifact.types before creating one to see each type's required files and recommended producing skill. Optional recipe_instance_id / step_id link an artifact to a recipe run for UI grouping.

Custom renderers

Shadow or add a type by writing a workspace renderer at .clawdevbox/renderers/<type>.mjs (via renderer.write). A renderer exports a default object with a render(root, ctx) function:

export default {
  type: "my-type",
  async render(root, ctx) {
    const data = await ctx.fetchFileJson("data.json");
    root.textContent = JSON.stringify(data, null, 2);
  },
};

See Extensibility → custom renderers for the full contract.

Artifact & renderer tools

ToolPurpose

artifact.typesList supported artifact types with required files, schemas, and recommended skills.
artifact.list / artifact.getList artifacts / read one artifact's manifest + content.
artifact.deleteDelete an artifact and its on-disk payload.
artifact.comment_replyReply to a comment thread on an artifact (e.g. a PR-review comment).
