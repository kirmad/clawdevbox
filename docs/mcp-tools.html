MCP Tools Reference

ClawDevbox exposes 114 tools across ~18 namespaces. Everything an agent does — running recipes, firing triggers, reading memory, publishing artifacts — is a namespaced MCP tool call.

The meta-tool gateway

To keep schema tokens small, every tool is gated behind three meta-tools. Discover, learn the schema, then execute — you only pay for the tools you actually use.

list_tools → learn_tool → run_tool
Meta-toolPurpose
list_toolsList available tools with one-line descriptions. Key param: filter (substring).
learn_toolReturn full JSON schema, examples, and docs for one or more tools. Batch names in one call.
run_toolExecute a tool by name. Pass params via args; refuses tools you haven't learned this session.

run_tool passes wrapped-tool params via the args key — not arguments. Passing arguments is silently ignored and the tool runs with empty params.

list_tools({ filter: "recipe" })
learn_tool({ tools: ["recipe.template.upsert", "recipe.instance.begin"] })
run_tool({ tool: "recipe.instance.begin", args: { id: "pr-review", prompt: "…" } })

Plugin-contributed example

Plugins add their own namespaced tools. The bundled ADO plugin contributes an Azure DevOps toolset, and the pr-walkthrough plugin adds a walkthrough Q&A tool:

ToolPurpose
ado.get_pr / get_pr_status / create_pr / comment_prRead, create, and comment on Azure DevOps pull requests.
ado.list_pr_commentsList a PR's comment threads.
ado.get_work_item / update_work_item / list_work_itemsRead, update, and query work items.
ado.add_work_item_comment / list_work_item_comments / get_work_item_updatesComment on and audit a work item.
ado.list_iterationsList a team's iterations / sprints.
pr-walkthrough.answerAnswer a question posed inside a PR walkthrough artifact.

The exact tool set depends on which plugins are installed. Run list_tools({}) against your own server for the authoritative, live catalog — that's the source of truth this page mirrors.
