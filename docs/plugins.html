Plugins

A plugin is a self-contained bundle of recipes, skills, triggers, hostable tools, renderers, and MCP configs that ships as one unit. Plugins are how capabilities are packaged and shared — install one and its whole set of assets becomes available across every project.

What's in a plugin

Recipes & skills

Multi-step templates and procedural knowledge, scoped to the plugin.

Trigger types

Reusable proactive capabilities others can register.

Hostable tools

Single-file TypeScript tools exposed as MCP tools.

Renderers

Custom .mjs renderers for new artifact types.

CLI providers

New agent CLI backends via clawdevbox.agent_clis[].

MCP configs

External MCP server definitions to wire in.

Plugins install under <global_dir>/plugins/<id>/ (a real directory for git/built-in installs, a junction for local-folder installs) and are read-only at runtime. The global store is shared across all workspaces.

The manifest

The canonical manifest is <plugin>/.claude-plugin/plugin.json — Claude-compatible fields plus a clawdevbox extension block for ClawDevbox-specific assets:

{
  "name": "ado-tools",
  "version": "1.2.0",
  "description": "Azure DevOps recipes, triggers and hostable tools.",
  "skills": ["skills/pr-iteration.md"],
  "mcpServers": {},
  "hooks": {},
  "clawdevbox": {
    "recipes": ["recipes/pr-review.yaml"],
    "tools": ["tools/get-pr.ts"],
    "trigger_types": ["trigger-types/pr-comment-watcher"],
    "agent_clis": [],
    "renderers": ["renderers/pr-review.mjs"]
  }
}

Discovery, scope & shadowing

Assets from a plugin resolve at plugin:<id> scope, between project and global. Project shadows plugin shadows global on id collision:

project shadows plugin:<id> shadows global

To customize a plugin-shipped recipe / skill / trigger, copy it into project scope and edit there — writing to plugin:* scope is rejected because plugins are read-only.

Hostable tools

A hostable tool is a single-file TypeScript tool inside a plugin's tools/ directory, exposed as a namespaced MCP tool without standing up a full external MCP server. See Extensibility → hostable tools for the authoring contract.

Installing plugins

Install from a git URL, a local folder, or a marketplace catalog (a git-backed catalog of plugins). A built-in marketplace ships with ClawDevbox.

# From git (optionally pin a ref)
clawdevbox init --plugin git+https://example.com/ado-tools.git

# From an MCP tool call
run_tool plugin.install { "from": "git+https://…/ado-tools.git", "ref": "v1.2.0" }
run_tool plugin.install { "from": "C:\\dev\\my-plugin" }   # local folder

Plugin tools

ToolPurpose
plugin.listList installed plugins with manifest summary + load status.
plugin.readRead a plugin's full manifest, provides listing, install origin, and status.
plugin.installInstall from git+https, git+ssh, or an absolute local path.
plugin.updateFor git-installed plugins, pull & re-validate the manifest.
plugin.uninstallRemove the plugin directory + install record (project overrides survive).
plugin.enable / plugin.disableToggle whether a plugin is loaded, without deleting it.
