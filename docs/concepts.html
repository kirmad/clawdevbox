Introduction

Core Concepts

ClawDevbox has a small, sharp vocabulary. Learn these terms once and the rest of the docs read easily. Each primitive is a file on disk and a set of MCP tools — nothing is hidden in the host.

The mental model

Three primitives cover most of what agents do, split by the question they answer:

Recipe = WHAT

A multi-step pipeline of goals the agent runs and adapts.

Skill = HOW

Procedural knowledge the CLI auto-loads to do a step well.

Trigger = WHEN

A cron / webhook / manual script that decides when to act.

Authoring primitives

Recipe

A reusable, multi-step task template (TaskDock-style) that the agent uses as a starting point and adapts. A recipe declares id, name, description, and an ordered steps[] array, each step a human-readable goal with optional agent instructions and dependencies. The template lives on disk; each run mints an instance. → Recipes guide

Skill

A markdown file with YAML frontmatter (name + description) that the side-terminal CLI auto-loads as procedural knowledge. Skills capture the how: a repeatable workflow, a house style, a guardrail. They carry a feedback loop that promotes proven skills and demotes stale ones. → Skills guide

Trigger

A trigger type is a capability — a script plus a parameter schema and default cron. It doesn't fire until you create a registered instance bound to concrete params. Instances fire on cron, via webhook, or manually, receiving a JSON envelope on stdin and persisting state on stdout. → Triggers guide

Plugin

A self-contained bundle of recipes, skills, triggers, hostable tools, renderers, and MCP configs that ships as a unit. Plugins install under <globalDir>/plugins/<id>/ and are read-only at runtime — customizations go in project scope. → Plugins guide

Runtime primitives

Workspace

An isolated directory (<workspaces_root>/<id>/) holding a .clawdevbox/ state tree plus an artifacts/ folder. Every recipe run gets one so agents never step on each other. The canonical registry is <workspaces_root>/index.json.

Artifact

A folder at <workspace>/artifacts/<id>/ containing a manifest.json plus content files. The manifest's type selects a renderer at view time — markdown, pr-review, or walkthrough out of the box. → Artifacts & Renderers

Hostable tool

A single TypeScript file inside a plugin's tools/ directory that ClawDevbox discovers and exposes as an MCP tool. A lightweight alternative to a full external MCP server: it exports an id, a description, a parameters zod schema, and an execute(args, ctx) function. → Author one

Scope

Where a recipe / skill / trigger comes from. On id collision, more specific scopes win:

project shadows plugin:<id> shadows global

To customize a plugin-shipped asset, copy it into project scope and edit there — plugin scope is read-only.

Workflow entities

These live in the SQLite kernel and back the inbox / session experience:

Inbox item
A row representing one actionable thing (a PR, work item, incident, epic, or manual ask). The user's primary view. → Inbox & Workflow
Thread
One ongoing run for an inbox item. Recursive via parent_thread_id, which builds the epic decomposition tree.
Message
An append-only log entry on a thread — agent text, a tool call, a tool result, a view emission, or a user message.
Approval
A pending user decision an agent surfaced. The agent's interrupt; resolved through an approval round-trip.
Session
A running agent CLI in a hidden pty. Browser viewers attach live; session.* tools read and drive it. → Agent Sessions
Memory
Durable knowledge — facts, lessons, and wiki — in git-backed personal + team vaults. → Memory
