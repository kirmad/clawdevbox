Building Blocks

Skills

A skill is a markdown file with YAML frontmatter — procedural knowledge the CLI auto-loads at runtime. Skills capture the HOW: a repeatable workflow, a house style, a guardrail or checklist. Recipes say what to do; skills say how to do it well.

Storage & scope

Skills resolve project → plugin → global; the more specific scope shadows the rest on id collision.

ScopePathWritable
project<projectDir>/.clawdevbox/skills/<id>.mdyes
plugin:<id><globalDir>/plugins/<id>/…read-only
global<globalDir>/skills/<id>.mdyes

Frontmatter

Only name and description are required. The description is the trigger surface — write it so the skill is found when it's relevant.

---
name: run-npe-tests
description: >
  Discover the NPE pipeline + suite, deploy, run, and gate a change in a
  non-production environment. Use before opening a PR and after every change.
---

# Run NPE tests

1. Discover the pipeline and suite for the service...
2. Deploy the branch to the NPE ring...
3. Run the suite and gate on green.

When to author a skill

  • You did the same multi-step thing ≥2× in one session.
  • The user said "remember how to do X" or "next time do it this way".
  • The workflow has a critical "do not skip" step (TDD, lint, a security gate).
  • The output needs to be consistent, or a helper script would make it repeatable.

Reuse existing skills, never dump raw step text, and keep them reusable. Plugin-shipped skills are read-only — copy one into project scope to customize it. Author with skill.upsert.

Feedback & promotion

Skills carry an implicit, privacy-safe feedback loop (no identity or message content stored). Record signals with skill.feedback.record, roll them up with skill.feedback.aggregate, and review candidates with skill.feedback.pending. Aggregation computes rolling 7d/30d counters and a score_30d. Promotion/demotion applies only across project ↔ global (plugin skills are immutable):

Promote project → global

  • score_30d > 0.75
  • uses_30d ≥ 10
  • errors_30d = 0

Demote global → project

  • score_30d < 0.30 for ≥ 14 days, or
  • errors_30d ≥ 3

There's a 14-day no-demotion window after promotion; corrections surface once corrections_30d ≥ 2.

Skill tools

ToolPurpose
skill.listList skills across scopes (project + plugins + global).
skill.readRead a skill's markdown body + parsed frontmatter + resolved scope.
skill.upsertCreate or update a skill in project or global scope.
skill.deleteDelete a skill from project or global scope.
skill.feedback.recordRecord an implicit feedback signal (dedup'd to one vote / session / skill / day).
skill.feedback.aggregateAggregate signals into rolling counters + score_30d.
skill.feedback.pendingList skills with pending corrections or promotion/demotion candidacy.
