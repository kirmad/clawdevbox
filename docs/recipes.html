Building Blocks

Recipes

A recipe is a reusable, multi-step task template — the WHAT. It declares an ordered list of goals; the agent reads them as a starting point and adapts. Recipes are executable state machines, whereas skills are documentation.

Recipe = WHAT, skill = HOW. Use a recipe when the workflow is deterministic and repeatable. For one-off work, inline it. For "the user keeps asking for this", elevate it to a recipe.

Recipe shape

A recipe template (stored at .clawdevbox/recipes/<id>.yaml) has these top-level fields:

FieldTypeMeaning
idstringKebab-case id (matches the file name).
namestringShort display name shown in recipe.template.list.
descriptionstring1–3 sentence summary of what the recipe does.
kindenumworkitem · pr_review · incident · epic · custom.
default_clientenumWhich CLI runs it: copilot · claude · echo-stub.
mcp_serversstring[]MCP server ids the recipe needs.
stepsarrayOrdered array of step objects (below).

Step shape

FieldRequiredMeaning
idyesKebab-case id, unique within the recipe. Addressed by recipe.steps.update_status.
goalyes≤200-char human-readable TL;DR shown as the step title in the UI.
ai_instructionsnoFull agent-facing prompt (≤16000 chars). Reference specific tools, commands, skills.
dependsnoArray of step ids this step waits on — enforces topological order.
requirednoWhen true, the step cannot be skipped (a non-negotiable gate).
params · artifacts · triggersnoStep-local param declarations, artifact declarations, and triggers materialized on step entry.

A worked example

A small, idempotent 2-step recipe:

id: cleanup-stale-branches
name: Prune merged remote branches
description: >
  Delete branches already merged to main. Idempotent — safe to re-run.
kind: custom
default_client: copilot
mcp_servers: [clawdevbox]
steps:
  - id: scan
    goal: List branches merged into main
    ai_instructions: |
      Run `git branch --merged main` and parse the output. Exclude
      `main`, `master`, and any `release/*` branch. Save the list for
      the next step to consume.
  - id: prune
    goal: Delete each merged branch (with confirmation)
    depends: [scan]
    required: false
    ai_instructions: |
      For each branch from step `scan`, ask the user via the inbox before
      deleting. On confirmation run `git branch -d` and push the delete.

Validation gates & the step machine

You advance each step with recipe.steps.update_status — set it before starting a step and after finishing it, every time. The status machine is monotonic:

pending → in_progress → done · failed · skipped

A step can declare validation gates. When you mark such a step done, it enters a validating state and an independent verifier session is spawned; it writes a { verdict, evidence, gaps } record and only then is the step accepted (or bounced back). Steps marked required: true reject any skipped transition.

Record evidence in durable state / result (not only the free-text message) — some gates inspect instance state or the workspace, not the session transcript. Pass recipe_instance_id explicitly if you're on a bifurcated lane console.

Lanes & sessions

A step may declare an execution.session lane. A lane-dispatch worker spawns or wakes an interactive console per lane, so, for example, implementation and review steps can run in separate agent sessions. Lane main is the initial console the run started in.

Template → instance lifecycle

  1. Author the template

    recipe.template.upsert writes the reusable YAML (project or global scope; plugin scope is read-only).

  2. Begin an instance

    recipe.instance.begin mints a run instance, resolves a workspace, and spawns the agent CLI. The instance id is injected as CLAWDEVBOX_RECIPE_INSTANCE_ID.

  3. Advance the steps

    The running agent calls recipe.steps.update_status as it works, and recipe.instance.update_steps to mutate the materialized plan.

  4. Observe & finish

    recipe.instance.view_url gives a live PTY viewer; recipe.instance.get reads the durable row; recipe.instance.kill cancels a run.

Recipe tools

ToolPurpose
recipe.template.listList recipe templates across project, plugin, and global scopes.
recipe.template.getRead one template's parsed structure + raw source.
recipe.template.upsertCreate or replace a recipe template (shape-validated).
recipe.template.deleteRemove a template.
recipe.instance.beginStart a run instance and spawn the agent CLI.

recipe.instance.list_runningList live recipe PTY sessions.
recipe.instance.view_urlGet a browser URL to attach to a running instance's PTY.
recipe.instance.update_stepsMutate the materialized step plan (add / remove / update).
recipe.instance.killCancel a running instance.
