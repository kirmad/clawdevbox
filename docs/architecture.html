Introduction

Architecture

ClawDevbox is a thin substrate around your coding agent. Its only durable state is a single SQLite file; it exposes that state as an MCP server, runs a cron daemon for triggers, and spawns your agent CLI in a hidden pseudo-terminal. That's the whole engine.

The key inversion

The most important design decision: the sidecar does not run an agent loop — your CLI does. ClawDevbox's job is to keep the SQLite tables consistent, expose them over MCP, and wake CLIs up when trigger scripts demand it. The agent (Copilot, Claude, Cursor) drives its own loop and calls MCP tools to record what it does. This keeps the host small, testable, and provider-agnostic.

Four moving parts:

The kernel

A single SQLite file — the only durable state. Everything else is derived or re-scannable.

The MCP server

Streamable-HTTP surface exposing every verb as an MCP tool. The primary API — the WS facade is a convenience layer over the same handlers.

The cron daemon

An in-process scheduler that ticks each trigger on its cadence, spawning a worker per tick that decides whether to fire.

The side terminal

Your agent CLI, spawned in a hidden node-pty (ConPTY on Windows). Browser viewers subscribe over WebSocket.

The kernel

Durable state is six logical tables in one SQLite file (plus schema_version and a settings_kv). All access goes through a single library; schema changes are additive only.

TableWhat it holds
inbox_itemsOne actionable thing (a PR, work item, incident, epic, manual ask). The user's primary view.
threadsOne ongoing run for an inbox item. Recursive via parent_thread_id (epic trees).
messagesAppend-only log entries on a thread (agent text, tool calls, results, views).
triggersRegistered trigger instances + their persisted state and last-run audit.
approvalsPending user decisions an agent surfaced — its interrupts.
artifactsFiles an agent registered (review markdown, walkthroughs, aggregates).

The file is the state. A crashed sidecar recovers by re-scanning on-disk records (e.g. recipe-instances/), because the row on disk is the durable record of what's running.

The MCP surface

The sidecar runs an HTTP MCP server (Streamable HTTP) on a localhost port (default 5201). It is the primary surface. Auth is a per-launch 32-byte hex secret in the Authorization header, minted at boot and written into the agent's MCP config. The surface has three faces:

Tools (verbs)

114 namespaced tools — recipe.*, trigger.*, skill.*, inbox.*, memory, and more — reached through the list_tools / learn_tool / run_tool gateway.

Resources (nouns)

resources/read returns JSON documents for inbox items, threads, artifacts, and recipes by URI — no round-trip through tools.

Notifications (stream)

The sidecar emits notifications/resources/updated whenever an item, thread, or approval changes. The viewer subscribes over WS.

The side terminal

This is the load-bearing inversion. What runs in the terminal is your installed CLI — ClawDevbox does not bundle it. The flow:

  1. Configure

    At boot the sidecar writes an MCP config (.mcp.json) with the streamable-http URI and the per-launch bearer token, plus any extra servers from .clawdevbox/mcp/*.json.

  2. Spawn

    The recipe runner spawns the CLI detached inside a hidden pty (e.g. copilot --allow-all-tools / claude -p) and hands it a system prompt describing the recipe, available tools, and the discipline of recording progress.

  3. Observe

    Every meaningful CLI action is mediated by an MCP tool call. The viewer tails the thread's messages and renders — while browser viewers stream the raw xterm over WebSocket.

Install modes

Global recommended

<globalDir>/config.json holds account-wide settings (port, bearer token, tunnel, notifications, plugin set). Plugins live under <globalDir>/plugins/ and are shared across every project. Launch from any directory; the cwd becomes project_dir.

Project-specific

Writes <projectDir>/.clawdevbox/config.json. Only takes effect when the server is launched against that project. Useful when a particular repo needs a different port / token / tunnel.

Background service

clawdevbox start --service spawns the HTTP MCP server detached and registers an OS-level auto-start entry so it relaunches at every login — Task Scheduler (Windows), a LaunchAgent (macOS), or a systemd-user unit (Linux, plus loginctl enable-linger for logout survival). <globalDir>/service.json records the PID + port + version so stop and status always find the running instance.

Security model

VectorMitigation
Random local process pokes the MCP serverPer-launch 32-byte hex secret in the Authorization header, validated in middleware.
Malicious extension reads unrelated envA disallowed-keys blocklist applied to every spawned MCP child.
PII leak to the LLMA bidirectional scrub layer distinguishes structural vs data GUIDs and round-trips them.
Secrets embedded in recipesRecipes never carry secrets; MCP configs reference env-var names resolved from the OS keychain at spawn time.
Approval forgeryApprovals carry a renderer-minted nonce; approval.resolve requires it.
Trigger script flood / runawayPer-trigger timeout; the cron daemon serialises ticks per trigger; failing scripts log and continue from last good state.
Codename: Conductor

The internal namespace is Conductor — you'll see it in env vars (CLAWDEVBOX_*), on-disk paths (.clawdevbox/), and the engine's internals. The branding is ClawDevbox; the engine underneath is the Conductor MCP server. The name is load-bearing and stable.
