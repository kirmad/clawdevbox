Building Blocks

Memory

Memory is what makes each session smarter than the last. Agents recall what's known before acting, capture what they learn after, and vote on what they used. Everything is git-backed markdown in vaults, so knowledge is portable, reviewable, and shareable.

The three memory types

Fact

A short atomic searchable truth — a preference, path, convention, or gotcha. Ranked by vote tally.

Lesson

An insight from a mistake or hard debug — a non-obvious gotcha or ordering constraint. Confidence decays without reinforcement.

Wiki

A curated doc, SOP, or architecture overview — a multi-step reusable procedure. Ranked by vote tally.

Facts

Use for conventions, decisions, env details, and gotchas a future agent should remember. Facts require citations (file:line or an exact user quote) and a reason.

ToolPurpose
add_factSave a durable atomic fact (needs content + scope + citations + reason).
get_factFetch facts for a path / scope.
vote_factUp/down-vote a fact (adjusts its rank).

Lessons

Use for hard-won heuristics — the kind of thing you'd want future-you to weigh from the first turn. get_lessons is the session-start preload of top personal + team lessons.

ToolPurpose
add_lessonSave a confidence-scored heuristic.
get_lessonsReturn top-ranked lessons for session-start context.
vote_lessonReinforce or weaken a lesson.

Wiki

Use for overviews and reusable procedures. Keep wiki pages current — but only update one when you're highly confident the change is final (user approved or code checked in).

ToolPurpose
upsert_wiki / add_wiki_pageCreate or update a curated wiki page.
update_wikiPatch an existing page.
get_wiki_indexBrowse the wiki tree.
vote_wikiVote on a page.

Vaults

Memory lives in vaults resolved as a chain — personal → team. Each search accepts a scope, or you can pin a specific vault_id.

VaultMeaningSync
personalOne user's private knowledge, across all repositories.Optional backup.
teamShared across the team; applies to everyone in a repo.git-synced.

search_memory takes scope: "personal" | "team" | "all" and a types filter. Team vaults sync through git — memory_sync pulls/pushes, memory_init bootstraps a vault, and memory_status reports vault health.

Recall → record → vote

  1. Recall — before you derive

    Session start: get_lessons({}). Before substantive work: search_memory({ query, scope: "all" }) — "have we solved this before?" For a specific file: get_fact({ path }).

  2. Record — after substantive work

    add_fact for atomic facts, add_lesson for heuristics, upsert_wiki for curated docs. Judge value: will this save time or prevent an error next time?

  3. Vote — close the loop

    Up-vote memories that helped; down-vote wrong or stale ones and write a corrective fact in the same turn. Voting is what keeps the knowledge base self-correcting.

This loop is orchestrated automatically by the auto-learn and using-memory skills. Don't re-derive what memory already knows — search first, derive second, record after.

What's worth recording

Record

  • High-cost mistake + its fix (lesson)
  • Unintuitive param or prerequisite (fact)
  • A user preference or convention (fact)
  • A reusable process or template (wiki)

Don't record

  • One-off Q&A with no reusable process
  • Generic concepts findable online
  • Ephemeral "for now" instructions
  • Secrets, credentials, or PII
